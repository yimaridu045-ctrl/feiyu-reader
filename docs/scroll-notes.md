# 滚动实现记录

## 现状（v2.0）

- 文本区用 `RichTextBox` + 窗口 `WS_EX_COMPOSITED`（整窗合成）解决滚动拖影；
- 滚动交给 RichEdit 原生处理，**不做自定义像素平滑**；
- 自定义平滑滚动代码保留在 `src/BufferedTextBox.cs`，由 `SmoothEnabled`（配置 `smoothScroll`）控制，默认关闭。

## 为什么不启用像素平滑

尝试用 `EM_SETSCROLLPOS`（像素坐标）做逐帧缓动，问题链：

1. **连续滚轮丢距离**：每次从当前位置重启动画，会丢弃上一次剩余距离 → 改成累加目标；
2. **越界值让 RichEdit 丢位置**：目标超出内容范围时，视图会跳到不可预期位置（表现为"弹回/跳走"），
   极端情况下滚进内容下方出现大片空白；
3. **最大滚动位置难测**：
   - 用末字符 `GetPositionFromCharIndex` 估算 → 偏小，只能滚到 69~80%；
   - 设极大值让 RichEdit 夹住 → 不可靠，会接受超出内容的距离；
   - 二分查找 + `WM_SETREDRAW` 关重绘 → 数值正确，但测量过程仍会带来观感问题。

结论：在 RichEdit20 上做像素滚动不稳定，故默认关闭。

## 如果以后要再做

建议只对 `EM_LINESCROLL` 做行级小步动画（每格 3 行、每 30ms 一行）：
边界由 RichEdit 自己管理，不可能越界，代价是粒度是"行"而非"像素"。
